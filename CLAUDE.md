# rl-for-llms: context for AI assistants

## What this is

A Quarto book (*Reinforcement Learning for Language Models, from First Principles*) plus a small
numpy package, `rl4llm`, of toy experiments on an **enumerable language** where the optimal
policy, every KL and the true policy gradient are computed exactly.

Read these before changing anything; they carry the "why":

- **`SPEC.md`** (local only, gitignored): the conceptual contract (theses, chapter architecture,
  method cards, figures). If it is absent, `CONVENTIONS.md` and `ROADMAP.md` carry what it decided.
- **`CONVENTIONS.md`**: how chapters, method cards, lineage callouts and figures are written.
- **`ROADMAP.md`**: chapter status, the final chapter plan and *why it deviates from the spec*
  where it does, the figure and experiment lists, and the decision log.
- **`research-log.md`**: every source and what was verified in it. Check it before stating any
  technical claim; add to it whenever a new source is used.

## Two rules that override convenience

1. **Never write technical content from memory.** Verify methods, equations, defaults, dates and
   results against the primary source (paper, official report, official blog) and log it in
   `research-log.md`. Secondary explainers are for orientation only.
2. **It is an RL book.** Every paragraph should help the reader understand an RL technique or
   how a modern method relates to classical RL. Topics owned by sibling repos
   (`../loss-functions-lab`: Bradley–Terry, DPO derivation, proper scoring rules;
   `../transformer-atlas`: architecture) are linked, not re-derived.

## Architecture

```
src/rl4llm/
  toy_language.py   ToyLanguage (V, L, prompts; prefix bookkeeping), prefix-tabular policy
                    (logits shape (P, n_prefixes, V)), make_reference (MLE on a synthetic
                    corpus), correctness_reward, optimal_logprobs (exact pi*)
  metrics.py        exact KL / expectation / entropy / pass@k by enumeration
  estimators.py     advantages (none/mean/rloo/grpo), k1/k2/k3, PPO clip objective + gradient
  methods/          one module per method; module docstring = method card; every method
                    ends in grad_log_likelihood(lang, logits, prompts, responses, weights)
    _common.py      Adam + History (exact KL-to-pi*, KL-to-ref, reward during training)
tests/              exact numerical checks of the book's derivations
scripts/figures/    fig_<slug>.py, one per figure; imports rl4llm; writes docs/images/<slug>.png
docs/               Quarto book; Quarto does NOT execute code (figures are committed PNGs)
```

## Conventions and gotchas

- **`grad_log_likelihood` is the whole book in one function** (Thesis 2: every method is a
  sampling distribution `q` plus per-sample weights `w`). New methods must go through it, not
  around it.
- **The policy is prefix-tabular on purpose**: it can represent `pi*` exactly, so "did the method
  reach `pi*`?" is never confounded with model capacity. Don't swap in a per-position table.
- **Sampling is from the exact joint distribution** (`sample_sequences`), which is
  distributionally identical to token-by-token sampling and much faster at this size.
- Changing `make_reference`'s defaults changes `pi_ref` for **every** figure: regenerate all
  figures and re-check the numbers quoted in chapters.
- Figure colors follow method *families* (`FAMILY_COLOR` in `scripts/figures/_theme.py`), never
  ad hoc. Every multi-series figure needs a legend plus direct labels or distinct line styles.
- Run a figure script, then **look at the PNG** before calling it done.
- In prose, link chapters by title, not by number.
- Do not commit or push without the author's go-ahead.

## Dev workflow

```bash
uv sync --extra figures --extra dev
uv run pytest
uv run ruff check .
uv run python scripts/figures/fig_<slug>.py
quarto render docs        # Quarto CLI must be installed separately
```
